# Migration Guide: v0.3.0 - Index Tree Viewer

## Overview

Version 0.3.0 introduces `get_index_tree`, a new MCP tool that visualizes the directory structure of indexed codebases with file and chunk statistics.

## What's New

### For Users

**New capability!** You can now visualize your indexed codebase structure without filesystem access.

**What You Can Do**:
- View indexed directory structure with file and chunk counts
- Verify what files were successfully indexed
- Navigate large codebases efficiently with subdirectory filtering
- Choose between tree or list format for different use cases
- Control output size with depth limiting

**Quick Start**:
```bash
cd /project
claude
> show me the index tree for this codebase

# Agent calls:
get_index_tree({ path: "/project" })

# Output:
/project/ [1,234 files, 8,952 chunks]
├── src/ [856 files, 6,234 chunks]
│   ├── components/ [234 files, 1,892 chunks]
│   ├── utils/ [122 files, 892 chunks]
│   └── types/ [45 files, 234 chunks]
└── tests/ [234 files, 1,456 chunks]
```

### For AI Agents (CLAUDE.md)

**Token Efficiency**:
Replace multiple file system operations with a single `get_index_tree` call.

**Before v0.3.0**:
```python
# Multiple operations to understand structure (~2,000-4,000 tokens)
1. ls -la /project
2. tree -L 3 /project  # May not be available
3. find /project -type f | head -100
4. Parse and format output
```

**After v0.3.0**:
```python
# Single operation (~200-400 tokens)
get_index_tree({ path: "/project", depth: 3 })
```

**Token Savings**: ~1,600-3,600 tokens per codebase exploration (80-90% reduction)

**Common Use Cases**:

1. **Verify Indexing**:
```python
# After indexing, show what was indexed
get_index_tree({ path: "/project", depth: 2 })
```

2. **Focus on Subdirectory**:
```python
# Explore specific area
get_index_tree({
    path: "/project",
    relative_path: "src/components",
    depth: 3
})
```

3. **Architecture Overview**:
```python
# High-level structure without files
get_index_tree({
    path: "/project",
    show_files: false,
    depth: 4
})
```

4. **Programmatic Processing**:
```python
# List format for parsing
get_index_tree({
    path: "/project",
    format: "list",
    depth: -1  # unlimited
})
```

### For Developers

**New Tool Available**:

```typescript
interface GetIndexTreeParams {
    path: string;                    // Required: Absolute path to indexed codebase
    relative_path?: string;          // Optional: Filter to subdirectory (e.g., "src/components")
    depth?: number;                  // Optional: Max depth (default: 3, -1 = unlimited)
    format?: 'tree' | 'list';        // Optional: Output format (default: 'tree')
    show_files?: boolean;            // Optional: Show files or dirs only (default: true)
    include_stats?: boolean;         // Optional: Show counts (default: true)
}
```

**Example Usage**:

```typescript
// Basic tree view
const response = await get_index_tree({ path: "/project" });
console.log(response.content[0].text);

// Focus on subdirectory
const srcTree = await get_index_tree({
    path: "/project",
    relative_path: "src",
    depth: 2
});

// List format for parsing
const fileList = await get_index_tree({
    path: "/project",
    format: "list",
    depth: -1
});

// Parse the list
const lines = fileList.content[0].text.split('\n');
const directories = lines.filter(l => l.endsWith('/'));
```

## Parameters Reference

### `path` (required)
Absolute path to the indexed codebase. Must be a directory that has been indexed.

### `relative_path` (optional)
Filter to a specific subdirectory within the indexed codebase.

**Examples**:
- `"src"` - Show only src/ directory
- `"src/components"` - Show only src/components/
- Windows paths work: `"src\\components"` (normalized internally)

### `depth` (optional, default: 3)
Maximum directory depth to display.

**Values**:
- `1` - Only top-level directories
- `3` - Default, good balance for most codebases
- `-1` - Unlimited depth (use carefully on large codebases)

### `format` (optional, default: 'tree')
Output format.

**Options**:
- `"tree"` - Visual tree with box-drawing characters (default)
- `"list"` - Flat list, one path per line (better for parsing)

### `show_files` (optional, default: true)
Show individual files or directories only.

**Values**:
- `true` - Show both directories and files (default)
- `false` - Show only directories (good for architecture overview)

### `include_stats` (optional, default: true)
Include file and chunk counts.

**Values**:
- `true` - Show statistics (default)
- `false` - Hide statistics (cleaner output)

## Performance Considerations

### Token Usage

**Tree Format**:
- Small codebase (10 dirs): ~100 tokens
- Medium codebase (50 dirs): ~300 tokens
- Large codebase (200 dirs, depth=3): ~600 tokens

**List Format**:
- ~20% fewer tokens than tree format
- Better for large codebases

**Tips**:
- Use `depth: 2` or `depth: 3` for initial overview
- Use `relative_path` to focus on specific areas
- Use `show_files: false` for high-level structure
- Use `format: "list"` for programmatic processing

### Query Speed

- Fast metadata-only query (no content loading)
- Typical response: <100ms for 10K files
- No caching needed - queries are already efficient

## Troubleshooting

### "Codebase is not indexed"

**Solution**: Index the codebase first
```typescript
await index_codebase({ path: "/project" });
await get_index_tree({ path: "/project" });
```

### Empty tree / no files shown

**Possible causes**:
1. Indexing still in progress - check `get_indexing_status`
2. All files were filtered by ignore patterns
3. Wrong `relative_path` specified

**Solution**: Verify indexing status
```typescript
await get_indexing_status({ path: "/project" });
```

### Output too large

**Solutions**:
1. Reduce depth: `{ depth: 2 }`
2. Filter to subdirectory: `{ relative_path: "src" }`
3. Hide files: `{ show_files: false }`
4. Use list format: `{ format: "list" }`

### Path separator issues (Windows)

**No action needed** - Windows backslashes are automatically normalized:
```typescript
// Both work on Windows:
{ relative_path: "src\\components" }  // Windows style
{ relative_path: "src/components" }   // Unix style (preferred)
```
